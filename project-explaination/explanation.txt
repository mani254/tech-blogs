# Project: Technical Blogging Platform — Architecture & Development Context

I am building a modern technical blogging platform using an Nx monorepo.

## Technology Stack

- Monorepo: Nx Workspace
- Frontend: Next.js
- Backend: NestJS
- CMS: Payload CMS
- Database: MongoDB
- Authentication: Existing Better Auth implementation
- API State Management: TanStack Query
- Language: TypeScript

## Existing Workspace Context

The Nx workspace has already been initialized and contains an implementation from another project.

Do NOT initialize a new workspace or replace the existing Nx configuration.

Your first responsibility is to understand the entire existing workspace, including:

- Nx configuration and project graph.
- Existing applications and libraries.
- Package manager and lockfile.
- TypeScript configurations and aliases.
- Build, test, lint and formatting configurations.
- Existing authentication implementation.
- Shared utilities and reusable packages.
- Existing dependencies and their compatibility.

The existing workspace structure should be reused wherever possible. Remove obsolete implementation and project-specific code while preserving useful infrastructure and configurations.

The existing Better Auth implementation is important and must be preserved completely.

## Access Control

For the initial version:

- Users must be authenticated to access blog content.
- All published articles are completely free.
- Authenticated users can read the entire article.
- No payment gateway or subscription system is required.
- No partial-content restrictions are required.

Keep the authorization architecture extensible for future premium content and subscription functionality.

## Development Principles

Follow these principles throughout development:

1. Understand the existing workspace before changing anything.
2. Preserve working infrastructure and authentication.
3. Avoid unnecessary dependencies.
4. Use strict TypeScript.
5. Avoid `any` and unsafe type assertions.
6. Maintain clear application and package boundaries.
7. Keep packages independently maintainable.
8. Use consistent naming conventions.
9. Write detailed README files for every application and shared package.
10. Document important architectural decisions.
11. Validate builds, linting and tests after every major change.
12. Do not introduce unrelated features.
13. Prefer incremental implementation over large uncontrolled changes.

## Development Workflow

The project will be developed in three major phases:

**Phase 1:** Nx workspace analysis, cleanup, dependency upgrades, package architecture, application setup and authentication preservation.

**Phase 2:** Payload CMS installation, configuration, MongoDB integration, collections, content models and publishing workflows.

**Phase 3:** Next.js blogging frontend, technical content rendering, SEO, SSR, caching and performance optimization.

Each phase will be further divided into smaller tasks.

Do not jump to future phases without explicit instructions.

Before implementing a task, inspect the relevant existing code and understand its dependencies. After implementation, validate the changes and report what was changed, what was preserved and what remains.
